# Game QA Case Study: LAST TICKET

## Overview

This repository documents an independent exploratory gameplay testing session conducted on *LAST TICKET*, an indie horror game developed by RayZDev.

The purpose of this case study is to demonstrate practical skills in exploratory testing, defect identification, gameplay validation, and technical feedback documentation.

- **Game:** [LAST TICKET](https://ray-casting.itch.io/lastticket)
- **Developer:** RayZDev
- **Review date:** July 8, 2026
- **Version recorded in the original review:** v1.0.0
- **Testing approach:** Exploratory manual testing
- **Scope:** Gameplay mechanics, player interactions, collision detection, animations, controls, and environmental objects

## Testing Approach

I explored the game's mechanics and environments, focusing on unexpected behavior and potential gameplay defects.

The testing session covered:

- Player movement and collision detection
- Crouching and hiding mechanics
- Object interaction and item handling
- Animation behavior during gameplay
- Environmental geometry and clipping
- Input behavior and controls
- Progression and an in-game ticket event
- Visual presentation and text quality

The submitted gameplay recording documented my second playthrough. My first playthrough was unrecorded, so I had prior familiarity with the game and its navigation during the recorded session.

## Key Findings

The session identified several issues affecting gameplay functionality and presentation, including:

- Inconsistent collision boundaries around environmental objects
- Unexpected player positioning when crouching under furniture
- Incorrect animation behavior while hiding
- Inconsistent interaction availability during a guided sequence
- An item falling out of the playable area under specific conditions
- Unexpected character behavior when pressing certain keys
- A ticket event that did not appear to progress during the recorded session

Additional observations concerned mouse sensitivity, environmental visuals, and text quality.

Detailed observations are documented in [Bug Reports](bug-reports.md).

## Outcome

The developer provided positive feedback on the submitted review, specifically recognizing the identification of game-breaking bugs and gameplay glitches. The developer also acknowledged the feedback and indicated that an issue related to sequence handling might have occurred following an update.

This case study represents findings from a specific testing session. The issues listed here have not been independently retested against subsequent builds, and their current status is unknown.

## Skills Demonstrated

- Exploratory manual testing
- Gameplay and functional testing
- Defect identification and documentation
- Observation of collision and animation issues
- Analysis of player interactions
- Clear communication of technical findings
- User experience evaluation
